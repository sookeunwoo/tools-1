# context-pack

현재 작업 상태를 **4KB 이하 브리핑**으로 압축한다. 출력된 마크다운을 새 세션의 첫 프롬프트로
그대로 붙이면 작업 맥락이 복원된다.

## 왜 있는가

단답 continuation("계속해줘", "다시 해봐")이 많은 건 게으름이 아니라
**"새 세션을 열면 컨텍스트를 다시 만드는 비용이 크다"는 합리적 회피**다.
컨텍스트가 부푼 세션을 억지로 끌면 매 턴 대량의 캐시 컨텍스트가 재처리되고, 그게 비용이 된다.

이 툴은 **새 세션 시작 비용을 없애서** 세션 분리를 공짜로 만든다.

## 사용

```bash
dk run context-pack --input '{
  "repo": "my-service",
  "task": "정산 배치 예외 처리 핸들러 추가",
  "ticket": "ABC-1234",
  "dod": ["3회 재시도 후 DLQ 전송"]
}'
```

`.data.briefing`을 복사해 새 세션에 붙인다.

### 입력

| 필드 | 필수 | 설명 |
|---|---|---|
| `repo` | ✓ | 설정에 등록된 저장소 이름 |
| `task` | ✓ | 작업 한 줄 설명 |
| `ticket` | | 티켓 ID |
| `baseRef` | | 비교 기준. 생략 시 `origin/main` → `main` → `HEAD~1` 순으로 탐지 |
| `files` | | 대상 파일 명시. 생략 시 git diff에서 도출 |
| `dod` | | 완료 기준. 자동 생성 항목에 추가된다 |
| `budgetKb` | | 기본 4 |

## 출력 예시

```markdown
## 작업: ABC-1234 — 정산 배치 예외 처리 핸들러 추가

## 대상 파일 (이것만 건드린다)
- `src/OrderExceptionHandler.kt` (+82/-0) **(신규)**
- `src/OrderService.kt` (+12/-3)

## 확인된 사실 (git 근거)
- 브랜치 `feat/abc-1234` @ a3f1c9d, 기준 `origin/main`
- 미커밋 변경 2개 파일 — 세션 시작 전 커밋 여부를 정할 것
- 빌드 `./gradlew build` / 테스트 `./gradlew test`

## 완료 기준 (DoD)
- [ ] 3회 재시도 후 DLQ 전송
- [ ] 테스트 없는 변경 파일 1개에 테스트 추가
- [ ] `./gradlew test` 통과

## 모르는 것 (직접 확인 필요)
- 대응 테스트를 못 찾은 파일: `OrderExceptionHandler.kt`
- 호출 관계·트랜잭션 경계·외부 시스템 의존은 **확인하지 않았다** (trace-flow 이후)
```

## 설계 규칙

1. **4KB 예산 초과 시 자른다.** 대상 파일 수를 줄여가며 맞추고, 그래도 넘치면
   `truncated.hasMore`와 함께 "`files`로 범위를 좁혀라"를 `nextActions`로 돌려준다.
   브리핑이 비대해지면 이 툴의 존재 이유가 사라진다.
2. **추측하지 않는다.** "확인된 사실"에는 git에서 나온 것만 넣는다.
   나머지는 전부 "모르는 것"으로 내린다.
3. **DoD 체크리스트는 필수다.** 세션이 완결되지 않는 원인 중 하나가
   "언제 끝난 건지 정의가 없어서"다.

## v0 정확도 한계

`repo-map`/`trace-flow`가 아직 없어서 **git과 파일 구조에서 확인 가능한 사실만** 담는다.

| 담는 것 | 안 담는 것 (M2에서 추가) |
|---|---|
| 변경·신규 파일과 라인 수 | 호출 관계 / 트랜잭션 경계 |
| 브랜치·기준·최근 커밋 | 영향 받는 엔드포인트 |
| 빌드·테스트 명령 | 외부 시스템 의존 |
| 테스트 파일 존재 여부 (이름 규칙) | 실제 커버리지 |

`testGaps`는 **이름 규칙 휴리스틱**이다 (`Foo.kt` → `FooTest.kt` / `Foo.test.ts` 등).
규칙이 다르면 실제로 테스트가 있어도 갭으로 잡힌다. 그래서 갭이 있으면 `confidence`를 0.9로 낮춘다.
